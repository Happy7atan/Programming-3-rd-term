# Лабораторная работа: Нерекурсивная генерация бинарного дерева (`gen_bin_tree`)

## Описание задачи
Реализовать на языке Python нерекурсивную функцию `gen_bin_tree`, которая строит бинарное дерево заданной высоты `height` с корнем `root`, вычисляя значения левого и правого потомков с помощью переданных функций `left_leaf` и `right_leaf` (по умолчанию заданных через `lambda`-выражения).

Дополнительно исследовать альтернативные структуры данных (включая контейнеры из стандартного модуля `collections`) для хранения узлов бинарного дерева.

---

## Параметры варианта (Вариант №11)
* **Корень (`root`)**: `11`
* **Высота (`height`)**: `3`
* **Левый потомок (`left_leaf`)**: `root ^ 2` (`lambda x: x ** 2`)
* **Правый потомок (`right_leaf`)**: `2 + root ^ 2` (`lambda x: 2 + x ** 2`)

## Описание базового алгоритма
Для построения бинарного дерева **без использования рекурсии** применяется алгоритм обхода в ширину (**BFS — Breadth-First Search**) на базе двусторонней очереди `collections.deque`:
1. Создается корневой узел в виде словаря `{"value": root, "left": None, "right": None}` и помещается в очередь вместе с номером своего уровня `(tree_root, 1)`.
2. В цикле `while` из начала очереди извлекается узел (`popleft()`).
3. Если уровень узла меньше заданной высоты `height`, для него вычисляются левый и правый потомки, привязываются по ключам `"left"` и `"right"`, после чего добавляются в конец очереди с уровнем `current_level + 1`.
4. Использование `collections.deque` обеспечивает выполнение операций добавления и извлечения за константное время $O(1)$ и полностью исключает ошибку переполнения стека вызовов (`RecursionError`).

Код оформлен в соответствии со стандартами **PEP-8**, снабжен документацией по **PEP-257** (docstrings) и строгими аннотациями типов (`typing`).

## Исследование альтернативных структур данных

Помимо стандартного словаря (`dict`), для представления узлов дерева были исследованы контейнеры из модуля `collections` (`namedtuple`, `defaultdict`, `UserDict`), а также `dataclass(slots=True)`.

### Результаты замеров (высота дерева = 10, 1000 запусков)

| Структура данных | Память на 1 узел (байт) | Время (1000 деревьев) | Особенности |
| :--- | :---: | :---: | :--- |
| **`dict` (базовый)** | ~184–232 | ~0.28 с | Удобная сериализация в JSON, но большой расход памяти на хэш-таблицу каждого узла. |
| **`collections.namedtuple`** | **~64** | ~0.26 с | В **3 раза компактнее** словаря. Из-за неизменяемости (`immutable`) дерево собирается «снизу вверх». |
| **`collections.defaultdict`** | ~192–240 | ~0.35 с | Безопасное обращение к несуществующим ключам (возвращает `None` без `KeyError`), но требует больше памяти. |
| **`collections.UserDict`** | ~56 (+ словарь внутри) | ~0.95 с | Легко расширять собственными методами ООП, но работает медленнее всех из-за обертки на Python. |
| **`dataclass(slots=True)`** | **~48–56** | **~0.21 с** | Минимальный расход памяти, строгая типизация и возможность изменять поля (сборка «сверху вниз»). |

### Вывод
* Если важна **совместимость с JSON** без дополнительных преобразований — оптимален базовый **`dict`**.
* Если требуется **экономия оперативной памяти** и защита дерева от случайных изменений средствами модуля `collections` — лучший выбор **`collections.namedtuple`**.
* Для крупных деревьев, где важны одновременно **скорость, минимальный расход памяти и изменяемость узлов**, лучше всего подходит **`dataclass(slots=True)`**.
